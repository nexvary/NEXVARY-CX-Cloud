# NEXVARY CX Cloud — mandatory engineering charter

Owner: Nexvary Inc. | https://nexvary.com
Repository: nexvary/NEXVARY-CX-Cloud
Goal: a production-grade self-hosted unified communications platform with functional parity with FusionPBX, plus full native Android administration, visual telephony workflows, CRM, billing and optional Voice AI. All requirements below are mandatory product roadmap scope, not claims of existing implementation.

## Baseline and architecture
Read README.md and relevant existing architecture, installation, security, PBX, Telnyx, WebRTC and CRM/billing documentation. Reference https://docs.fusionpbx.com/en/latest/ and FreeSWITCH official documentation. Preserve working Laravel/React/TypeScript/PostgreSQL/Redis/FreeSWITCH architecture and existing Android code; use Kotlin/Compose for new native components where compatible. Do not copy third-party code without license review. Support standalone operation and explicitly documented FusionPBX coexistence/migration modes; never overwrite an existing PBX configuration silently.

## Required feature matrix
Track every item below individually in docs/FEATURE-PARITY.md as Verified, Partial, Missing or Blocked, with commit, test evidence, limitations and next action. Routes, static screens, mock data, disabled draft records and README claims do not establish completion.

- CX01 Installation: reproducible Debian/Ubuntu installer, existing-install detection, safe upgrades, HTTPS domain access, setup wizard, initial administrator, database/Redis/ESL connectivity, certificate reuse, rollback, migration and recovery. Test clean install and failed-install recovery.
- CX02 Core PBX: extensions, SIP credentials, registration, gateways/trunks, provider presets (Telnyx and generic SIP), DIDs, inbound/outbound routing, caller ID/privacy subject to carrier rules, number translation, codecs, SIP profiles, NAT, TLS/SRTP, device provisioning, dialplan editor, validation, actual configuration activation and rollback.
- CX03 Call features: transfer, hold/resume, waiting, parking, pickup, DND, forwarding, Follow Me, blacklist, business hours, holidays, day/night mode, dial by name, hot desking, feature codes, music on hold, announcements and audio management.
- CX04 Contact center: IVR, ring groups, queues, agents, distribution strategies, operator panel, live calls, authorized hangup, CDR, consent-aware recording, recording access and retention, audio/video conferences, voicemail and voicemail-to-email.
- CX05 Fax: fax extensions, PDF send/receive, inbox/outbox, delivery status, retry, fax-to-email, T.38 and G.711 fallback, authorized downloads, actual interoperability tests.
- CX06 Messaging and email: SMS/MMS provider integration, inbound signature-verified webhooks, outbound messaging, conversations, delivery status, consent and rate limits, SMTP/IMAP integration and email management; respect provider capabilities.
- CX07 Administration: tenants/domains, users/groups, granular RBAC, ACLs, MFA/recovery, device management, system variables, FreeSWITCH modules, menu configuration, service health, authorized service restart, audit, logs, backup/restore, updates, monitoring, alerts, fraud controls, destination restrictions, spending limits and emergency call freeze.
- CX08 CRM and billing: contacts, tickets, call/message linkage, rate tables, rating, balances, usage, invoices, reports, reconciliation and configurable plans; no live payment integration without approval.
- CX09 WebRTC and optional Voice AI: browser calling, secure signaling/media, opt-in transcription, translation, voice assistance and analytics with consent, retention controls, provider abstraction, usage limits and cost ledger. Core PBX must work without AI.
- CX10 Android full administration: extend existing versioned mobile API and native app. Every supported web administrative function must have equivalent authorized mobile operations, including create/edit/delete/enable/disable, activation, validation, status and rollback where applicable. Cover extensions, trunks/gateways, DIDs, SIP profiles, dialplan, IVR, queues, agents, recordings, fax, SMS, voicemail, CRM, billing, users, security, backups, services, logs and monitoring. Support multi-server profiles, QR pairing, secure manual connection, device revocation, MFA/step-up authentication, Android Keystore-backed token storage, Arabic RTL/English LTR, notifications and capability discovery. Provide real APK build and device/emulator tests. No unrestricted shell, SQL or raw ESL from mobile.
- CX11 Visual PBX Builder: web and Android graphical workflow creation/editing, reusable templates, triggers, conditions, time rules, branches, IVR, queues, destinations, fallback, preview/simulation, schema validation, loop detection, revision history, safe publish and rollback. Compile allowlisted workflows into actual PBX configuration; no arbitrary code execution.
- CX12 Product UX: glossy deep black, metallic silver frames, meaningful multicolor icons, restrained neon green/red status accents, accessible contrast, responsive desktop/mobile, bilingual Arabic/English RTL/LTR, guided setup, contextual help, separate About System and About Developer pages, real operational data and explicit empty/loading/error states.

## Mandatory navigation, themes and developer support
- Preserve familiar FusionPBX information architecture and menu ordering: Home, Accounts, Dialplan, Applications, Status, Advanced. Use the official FusionPBX documentation and actual menu reference to map submenus, labels and workflows; place Extensions, Gateways, Destinations, Inbound/Outbound Routes, IVR, Fax, Queues and other functions in their familiar categories. Keep Nexvary-specific CRM, Billing, Voice AI and mobile management in clearly labeled additional groups without disrupting familiar PBX navigation. Preserve role-based visibility, breadcrumbs and search. Do not copy protected branding or assets.
- Provide both Day (light) and Night (dark) UI themes across web and Android, with a prominent switch, optional system preference, persisted user choice, and consistent accessible contrast. Night retains glossy black and metallic silver; Day uses light surfaces and silver accents. UI theme is independent of telephony day/night routing.
- Use genuinely multicolor semantic SVG/vector or licensed icon assets, not monochrome outline icons or emoji substitutes. Use distinct colored dashboard/module cards with readable labels, meaningful status colors and consistent design tokens in both themes. Verify Arabic RTL and English LTR, desktop/mobile layouts, keyboard accessibility and actual screenshots in both themes.
- Add a dedicated Contact Developer / التواصل مع المطور function on web and Android, separate from About System and About Developer. Provide verified Nexvary support channels, website https://nexvary.com, and a support request form with subject, category, description and optional explicitly approved diagnostic attachment. Never invent contact details or claim delivery without a working transport. Redact secrets and personal call data; show delivery/error state and prevent spam. Do not transmit diagnostics automatically.

## Mandatory development ledger

After every completed or partial milestone append date, milestone/CX IDs, actual changes, test commands and results (live/simulated/unverified), commit/PR reference, merge status, remaining gaps and next task. Keep docs/FEATURE-PARITY.md as the separate per-function status matrix. Update both in the same development batch.

## Security and acceptance
Use HTTPS, least privilege, server-side authorization, tenant isolation, encrypted secrets, rate limits, signed webhooks, CSRF protection where applicable, safe XML generation, strict input validation, audit logs and confirmation/step-up for destructive operations. Never expose ESL port 8021 publicly. Never leak credentials or private call data into GitHub or logs. Use synthetic fixtures. Do not promise anonymous caller ID delivery, provider features or regulatory compliance without evidence. Recording and messaging must respect consent and applicable law.
Use a shared service layer for web/mobile, versioned API contracts and authorization parity tests. Test actual FreeSWITCH provisioning and calls in an isolated environment; distinguish simulated, live and unverified tests. Verify fax, SMS and other provider operations only with authorized test accounts and destinations. Capture actual running screenshots, not mockups. Test migrations, rollback, cross-tenant denial, failure paths and regression. Do not mark production-ready until real installation, security and recovery gates pass.

## Execution order and cost controls
1. Inspect current HEAD, active PRs and existing progress; establish concise feature matrix and ledger, without repeating completed work.
2. Prioritize installation and real provisioning (CX01–02), then core call features/contact center, fax/messaging, security/operations, Android parity and visual builder, CRM/billing and optional AI. Build mobile API parity incrementally alongside each server module rather than postponing all mobile work.
3. Work in bounded dependency-ready batches. Read only relevant files; reuse implementations; avoid full repeated scans, broad refactors, verbose logs, unnecessary subagents and retry loops. Run focused tests during development and full regressions before merge. No paid services or production server modifications without explicit approval.
4. Commit and push tested changes; update feature matrix and concise progress ledger with evidence. Merge only under explicit owner authorization applicable to this repository and PR; otherwise open/update draft PR. Never force-push or bypass checks. Stop for genuine blockers or material security/architecture decisions.
5. Report only completed work, tests, commit/PR links, blockers and next priority. Do not claim completion without evidence. Token savings never override correctness or security.
